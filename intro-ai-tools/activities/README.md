# `activities/` — the idea library, one file per module

Brainstorming material for the course's eight modules — researched options to pick from
when building each session, not finished lesson plans. Start at the
[activity map](../ACTIVITY_CONCEPTS.md) for the course-wide view (pillars, scaffold,
tool menu, top picks); come here when planning one specific module.

**How each file reads:**

1. **Start here — the picks.** A handful of activities fleshed out enough to teach from
   tomorrow: what it is, how it runs minute by minute, the floor for computer novices,
   the stretch for engineers, and what students walk away with.
2. **Full menu.** The rest of the researched options as a table — one row per activity,
   with scaffold stage, gist, and source.
3. A pointer to that module's section of the [games shelf](../ACTIVITY_GAMES.md), and a
   note on how the file grows over time.

**Conventions:** scaffold tags `show` / `assist` / `solo` ("I do / we do / you do");
🌟 marks instructor-seeded ideas; *(adapted)* marks activities assembled from real
techniques rather than copied from one documented lesson; every link is verified live
before it lands here (flagged in place when a site blocks automated checks).

**Why these activities:** the program maps to real job skills a dean or advisory board
can check — activities use the actual tools job postings name (Canva/Figma, Excel/Sheets,
Zapier/Make/n8n, GitHub, Cloudflare Pages), and every module file opens with a "Maps to
job skills" line naming them. Each file is independent so any
module can be deepened without touching the rest.
